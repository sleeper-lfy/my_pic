# 美术风格规范：守城持锤战士

版本源为 `profiles/tower_defense.yaml`，profile `tower_defense`、版本 `0.1.0`、状态 `experimental_unapproved`。以下是验收目标；当前样板尚未完全符合，不因已生成图片而自动修改标准。

## 设计目标

原创成年幻想守城战士，具有精致手绘 2D 卡通角色的设计感。银色额发、深色头发、方正成年脸、短胡须和酒红围巾作为身份锚点。优先级固定为：**美术质量 > 风格一致性 > 动画稳定性 > 可复用性 > 自动化**。

风格参考只用于轮廓可读性、紧凑比例和小尺寸完成度，不复制其他游戏角色、纹样或原始素材。Blender 几何代理、姿态图、Toon Shader 渲染不能被标作成品；它们只提供空间结构。

## 比例和轮廓

| 项目 | 标准 |
|---|---|
| 头身比 | 约 3.5 头身；以头顶至下巴的头高与站姿脚底高度比较，不包含武器/发丝尖端 |
| 年龄气质 | 成年英雄，肩胸有力量感；避免婴幼儿大眼和极短四肢 |
| 轮廓 | 头、肩、前臂、持锤侧形成清晰阅读顺序；武器不淹没脸部 |
| 双手 | 两手完整可辨；一手握锤，另一手自然配合动作 |
| 非对称细节 | 大肩甲、斜带、额发方向等按解剖左右锁定，反向视图不能直接镜像偷换 |
| 部件关节 | 肩、肘、腕、髋、膝旋转后不能出现空洞、硬切缝、重叠双线或明显拉长 |

当前 v002 虽已生成左右朝向，但造型仍偏修长，不能宣称满足 3.5 头身；非对称肩甲存在镜像倾向。需要对两个真实视图分别标注解剖左/右并重画一致性问题。B/C 实验组合又出现肢体过窄和身体层次重复，亦不能作为比例标准。

## 线条、色板、阴影与材质

线条使用深色彩色描边，外轮廓强于内结构，转折有粗细设计，避免统一黑色等宽线条和锯齿杂线。在目标 96 像素显示下，脸、握柄、衣装分层仍应可读；缩小后完全消失的装饰不应继续增加。

| 色值 | 角色用途 |
|---|---|
| `#405469` | 蓝灰主甲，建立主体大色块 |
| `#8f9ba5` | 冷灰金属亮部，避免全身碎亮点 |
| `#b27a4d` | 铜色边饰和锤子视觉焦点 |
| `#682639` | 酒红围巾/布料重点，固定身份记忆 |
| `#4b342b` | 深棕皮革/底层结构 |
| `#e7dcc5` | 暖象牙布料与明部平衡 |

色板是主色方向，不是要求所有抗锯齿像素只能有六色。阴影以三层设计块面为基准：亮面、固有色、暗面。高光用于解释材质和造型，不采用覆盖全身的真实金属碎反射。纹理克制，优先盔甲大结构、衣装折叠和少量磨损；不能以噪声填满 64 像素下看不清的空间。

同一角色不同帧的光源逻辑和阴影归属应稳定。画片本身的高光不会随 3D 朝向自动正确变化；需要视图/手型替换时明确定义，不用任意色彩抖动掩饰。

## 镜头与画布

正交投影，左右前方方位角 −45°/+45°、俯视角 12°；两视图应来自真实方向设计或独立结构相机。二维像素坐标左上原点。画布 256×256 RGBA，脚底目标锚点 `[128,232]`，全动画至少 8 像素安全边距。

画布尺度由角色和动作的共同范围确定，不随某一帧包围盒缩放。武器抬到最高或挥到最远时也必须完整。当前结构蓄力图出现约 3–5 像素顶部余量，虽然未直接裁切，但不满足 profile 的 8 像素要求；后续须一致调整相机尺度或动画，而非逐帧缩小。

必须在 64、96、128 像素和 256 像素查看。放大细节只辅助修图，不能代替实际显示尺寸判断。透明边缘应同时放在浅色、深色和中灰背景上检查，不允许残留底色光晕或意外半透明脏边。

## 武器和手部

先固定一把矩形钢铜锤 A，第二把使用不同锤头轮廓的 B。两武器独立保存，同一组动作可复用，但握柄直径、握点、锤头重心和遮挡必须按具体设计审查。

握持判据不只是挂点距离：应看到手指合理包覆握柄，拇指关系正确，手腕方向与手臂受力一致。斜向攻击时不能出现武器穿掌、漂浮在手前或手突然换边。需要时分别绘制手背、握柄、前景手指，并针对蓄力/击出/收势替换手型。

当前图集里的独立手掌和锤子只是候选；B/C 的平面前手覆盖仍不能证明包覆正确。若动态换装会降低质量，允许共享动作数据、按武器重新离线合成和修正关键帧，优先保住手部和武器的整体设计。

## 动画风格

正式动作包括待机、攻击、防御。攻击应有可读的预备、加速、打击和收势，躯干/肩/自由手自然参与，武器重量通过速度变化和身体反作用表达。待机避免无意义全身漂浮，防御要有明确的受力方向和稳定足底。

帧率、关键帧和停顿按动作需要确定，不用多复制帧制造产量，也不用减少帧数掩盖变形。本次四个诊断关键姿势及 13 插值采样仅用于压力测试，没有完成上述动作设计；正式待机、防御与另一视图仍未开始生产。

## 原画与部件交付规范

静态样板需要：左右视图、持锤与无武器的手型方案、两把独立锤子、正常尺寸与放大预览。确认后再拆分头部/头发、躯干衣装、骨盆衣摆、左右上臂/前臂/手、左右腿脚、可动披布及武器。每个部件应补全旋转后会露出的区域并留重叠余量。

AI 图集不等于已批准拆件；部件边界、透视、重复装饰和可变形区域需要逐件审查。不得把同一条围巾同时留在头部、躯干和披布上，造成组合后重复轮廓。部件尺寸、枢轴、局部握点和遮挡约束保存在独立元数据，不能只凭代码常数作为长期美术约定。

## 导出与验收

每帧 RGBA PNG 256×256；角色主体、武器与前景手部层应可按指定顺序恢复组合帧。Sprite Sheet 附 JSON，记录方向、动作、武器、frame rectangle、duration、root/foot/hand/grip/pivot、图层顺序、版本和文件 hash。预览允许有棋盘格，但实际导出不能把棋盘背景烘焙进 Alpha。

验收分三类独立状态：

1. **自动技术检查**：尺寸、Alpha、非空、数量/时序、裁切、锚点、缺件、重组、异常面积/轮廓等；通过只表示这些已执行检查没有发现对应问题。
2. **AI 视觉初审**：列出可见缺陷、疑似帧和不确定项；不能替代人的美术取舍。
3. **人工美术验收**：由用户或指定美术负责人对确切文件版本确认，记录意见；没有确认时始终 `pending`。

当前静态样板和 A/B/C 实验都未获得人工美术通过。进入正式多动作生产前，至少需要确认紧凑比例、两方向身份/非对称装备、双手握持和实际尺寸轮廓；不能以脚本退出 0 覆盖这些条件。
