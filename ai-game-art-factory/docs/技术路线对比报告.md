# 技术路线对比报告

> 后续修正：用户已否决此轮结果。下文为历史比较，不再据此推荐继续修补旧B/C。已查明其二维插值会导致肢体塌缩，当前必须先验证公开人体素体、真实层级蒙皮与原生动作，再重新比较2D路线。

结论：**优先继续 B 的“精修原画和拆件”，用 C 提供姿态/透视约束，A 保留为概念与手绘关键帧候选来源。三条路线当前均未通过角色美术验收。** 此结论基于下面的可查看实验，不是最终路线锁定；尚不足以进入两方向、三动作的正式生产。

## 比较条件

同一原创守城战士：深发色银色额发、短胡须、蓝灰铜饰护甲、酒红围巾。风格配置为 `profiles/tower_defense.yaml` 的 `0.1.0`，目标约 3.5 头身、256×256 RGBA，并查看 64/96/128 像素实际尺寸。

当前设备是 Linux 云端，Blender 4.3.2 与 Godot 4.6.3 可运行。ComfyUI 本地接口不可连接，未验证用户 Windows 或 RTX 3060 Ti 8GB 推理。因此 A 使用现有图像生成服务进行**一次联合四关键姿势**实验，不能把结果称为 ComfyUI/ControlNet 时序工作流验证。

路线的输入成熟度并不相等：A 的输出由图像服务直接设计完整人物；B/C 使用同一张尚未美术确认的透明 16 部件图集。B/C 可以公平比较“相同部件如何被两种驱动方式影响”，但不能用本次粗糙拆件的观感证明所有 2D 骨骼路线天生劣于完整重绘。

这里的 13 帧是四个诊断关键姿势之间插值的实验样本，并非为了以少量帧掩盖问题，也不是设计完成的最终攻击动画。C 尚未逐帧采样完整 3D 动画。B/C 的范围仅为 **front_left、attack、两把锤子**；未声称右前视图、待机、防御完成。

## 观察到的结果

### A：有完整人物设计感，但不能据此交付动画

联合生成并没有消除身份与空间错误：第 3 姿势的脸朝向和持锤侧变化，第 2 姿势顶端 Alpha 触边、末姿势右侧源图触边/裁切。武器、衣装的局部形状也需按帧对照。即使多个姿势在同一张画布中生成，也不能替代可控的连续序列约束。

本次没有使用 ControlNet 的 pose/depth/normal 条件输入接口，没有使用视频/时序一致性模型，也没有可公开记录的生成种子和底层模型版本。`reports/generation-route-a.json` 将这些限制明确标出。四张关键姿势不足以评价连续播放的闪烁或动态细节漂移；当前 A 的状态是**发现明确视觉失败，完整受控时序实验未执行**。

如果继续 A，需要在已有本地模型和许可清单确认后，选定一个可在 8GB 环境运行的具体工作流，以相同动作、参考和固定参数生成完整序列；记录峰值显存和失败帧。没有此证据之前，不承诺“逐帧 img2img + 相同 seed”能解决一致性问题。

A 的 256 像素诊断预览采用统一缩放后逐个 Alpha 包围盒居中/底部对齐，仅用于展示。原始底部范围相差约 20 像素，这种登记方式不是解剖脚底追踪，不能作为脚底稳定性证据，也不能修复源图裁切。`reports/route-a-qa.json` 虽记录包装格式检查通过，整体实验仍为 `rejected_experiment`。

### B：外观复用成立，拆件美术决定结果上限

四组 B/C 输出均通过当前基础格式/非空/分层重组检查。B 中两把锤子复用角色关键点和图集，角色纹理不会逐帧随机变化。这个结果支持继续研究 B。

实际视觉检查仍发现围巾/肩部重复接缝、肢体过窄、肘部僵硬，以及手掌平贴锤柄等问题；64/96 像素下轮廓不如原画紧凑。当前图集也不是精确分离的已确认原画，而是另一次 AI 生成的部件候选，有重绘和重叠补全成本。不能把“16 个块都存在”当作合格拆件。

更新后的检查通过独立逆仿射计算测量握点，当前四组最大误差约 9×10⁻¹⁴ 像素，说明枢轴映射精度正确；手指是否真正包覆握柄仍需专门图层与人工确认。大角度攻击需要关节补图、手型替换、局部网格变形或少量绘制关键帧，不能依靠任意拉伸所有部件解决。左右前方应有分别确认的美术视图，不能镜像非对称护甲。

### C：适合作为约束来源，尚未自动保住原画轮廓

Blender 已输出关节像素坐标和相机深度，说明“3D 姿态 → 2D 驱动”接口可行。其真实结构握点的最大误差约 5.96×10⁻⁸ 场景单位，但这只验证几何挂点。

C 使用相同绘制部件时保留了材质细节，却出现与 B 类似的拼接和形体损失。固定 front_left 画片不能因旋转缩放自动生成正确的新视角。右前结构视角还显示较大透视缩短：后续需要按投影视角选择部件、局部变形及例外关键帧。

当前部件合成仍采用固定局部层序；已有深度数据不等于已经实现按深度正确遮挡。手指、手背和握柄交织尤其不能用一个全局排序解决。

## 七个维度的比较

| 维度 | A 结构参考 + 重绘 | B 2D 原画 + 部件动画 | C 3D 驱动 + 2D 外观 |
|---|---|---|---|
| 美术质量 | 单姿势设计感较好；本次关键姿势一致性失败 | 上限取决于精修拆件；本次拼接观感失败 | 能沿用 2D 纹理；本次投影变形损害轮廓 |
| 角色一致性 | 已见脸朝向、持锤侧变化；不能判定稳定 | 固定部件可稳定复用；跨方向与补图一致性待验证 | 固定部件稳定；视角选择、缩短与替换图待验证 |
| 动画稳定性 | 只有 4 个联合关键姿势，完整时序未测 | 13 采样帧可播放；僵硬和接缝未过关 | 13 采样帧可播放；不是完整 3D 动作逐帧采样 |
| 武器扩展 | 生成模型可能改变握柄/手型，未验证稳定替换 | 两锤共享二维动作与独立武器层；手型需精修 | 两锤共享投影轨迹；武器体积变化仍需视角/遮挡修正 |
| 自动化程度 | 结构通道可复现；本次服务的模型/seed 不公开 | 仿射合成、导出可脚本化；精修拆件和关节审批保留人工 | 投影可脚本化；部件映射与例外帧仍需设计 |
| 新角色成本 | 每条动作都可能增加重绘修正；未计时量化 | 每方向精修拆件成本前置，动作可候选复用 | 除拆件成本外增加映射/投影调试；角色比例差异不能忽略 |
| 8GB 适配 | 未测；由具体模型、分辨率、条件网络决定 | 当前 CPU 合成可运行，不等于 Windows 已测 | 当前 Blender CPU 结构实验可运行；Windows 性能未测 |

不提供缺乏依据的百分比分数、产能或显存承诺。当前没有足够已验收角色来估算单角色商业生产成本。

## 下一次最有价值的实验

1. 先确认 v002 的设计方向，修正为真实 3.5 头身和一致的解剖左肩护甲；在 96 像素下验收轮廓、面部、双手、主色。
2. 对同一个已确认的 front_left 角色进行真正的分层精修，补足肩肘交界、握柄后的手掌、握柄前的手指以及被遮挡衣装；不要重新生成整个角色来掩盖接缝。
3. 用 B 重做 0.6 秒攻击压力测试，再把相同修正部件交给 C。对照关节、手型、剪影、重心和打击节奏；两锤分别检查柄径、握点与锤头遮挡。
4. 只有该静态和短动作样板通过人工确认后，扩展另一方向与待机/防御。运行时换锤若损失视觉质量，采用“同一动作数据 + 按武器离线重新合成/绘制”的折中。
5. A 的 ComfyUI 完整序列实验在本地工具与已有模型核实后补做，再决定是否用于特效丰富的特殊攻击关键帧。
