## 在 Windows 探查

在 `ai-game-art-factory` 目录打开 PowerShell，使用已有 Python：

```powershell
python scripts/factory.py doctor --output reports/environment-windows.json
```

本次云端报告不能代替这一步。探针可识别 PATH 和部分常见 Windows 安装位置；若找到的软件不在 PATH，后续命令需使用完整可执行文件路径或为当前终端配置 PATH。不会自动安装软件、模型或升级环境。

云端实测 Python 3.12.14、Pillow 12.3.0、numpy 2.3.5、PyYAML 6.0.3。`requirements-tested.txt` 只固定实验使用版本。若 Windows 缺少依赖，先在独立 venv 安装所需的小型 Python 依赖，避免覆盖现有 ComfyUI 环境。Blender、Godot 和 AI 模型不由此文件安装。

## 复跑实验

所有命令在项目根目录运行。`python` 在当前云机也可用 `python3` 替换。

```powershell
python scripts/factory.py structure
python scripts/factory.py experiment --route all
python scripts/factory.py review
python scripts/factory.py test
python scripts/factory.py godot-check
```

`structure` 需要 PATH 中的 Blender，实际调用后台 Python；原始命令见 `workflows/blender/structure_probe.py`。只生成结构图，绝不输出最终角色美术。`experiment --route A` 只重新包装已记录的图像生成结果，不会再次调用 AI 服务；生成提示词及参考文件在 `reports/generation-*.json`。当前 image_gen 不暴露种子/模型版本，不能保证像素级再生成。

`experiment --route B --weapon hammer_b` 只重算指定部件实验。两把武器分离保存在 `assets/weapons/hammer_a.png` 与 `hammer_b.png`，保持画布及握点约定后可编辑。**默认命令不覆盖武器编辑**；`scripts/parts_experiment.py --extract` 会主动从原始 atlas 重提取并覆盖，只有确需重建时使用。新轮廓若改变握点，必须人工校准布局，不能依赖归一化 `.5,.74` 自动适配任意武器。

`reports/build-state.json` 保存输入和输出 SHA-256。第二次执行命中 `REUSED`；输入、工具版本或输出完整性变化后重新构建。武器节点分别依赖各自 PNG，改 B 不使 A 节点失效。当前仍会廉价重算受影响 clip 的身体合成，没有实现跨 clip 的所有身体层运算缓存，也不会重复 AI 生成角色原画。配置为已支持的 tower_defense 256px 实验，部分布局/姿态参数仍在版本化脚本内；其他风格是扩展目标，不能仅改 YAML 即宣称支持。

## Godot

```powershell
godot --path workflows/godot
godot --path workflows/godot -- --capture
```

第二条需真实图形显示，截图保存在 `previews/parts_experiment/godot-actual-size.png`。它是现有 PNG 序列回放场景，尚非 Godot Skeleton2D 运行时骨骼。头部无界面检查只验证加载 4 条序列/52 帧；`factory.py godot-check` 会同时核对退出码和成功标记。图形截图的云端软件渲染复跑方式见 `workflows/godot/README.md`。

## 质量与美术门禁

`reports/structure/qa.json`、`route-a-qa.json`、`parts-experiment.json` 保存技术检查；`reports/acceptance.json` 区分技术、AI 初步视觉审查与人工验收。源图裁切风险不会因导出加边而消失。零握点误差不证明手指包柄。零脚锚误差也不证明自然重心和脚接触。

人工验收仍为 pending；没有自动批准命令。先确认静态美术方向，修订头身比例、非对称装备、关节补绘与手掌/锤柄交错，再审查样板。样板未过，不批量生产第二方向和三动作。需要用户 Windows 上的实际能力报告后，才能继续本地 ComfyUI 和 8GB 显存验证。
