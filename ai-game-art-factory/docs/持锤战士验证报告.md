## 自动技术结果

- Blender 16组/80图通过格式、非空、边缘未触线、臂长和挂点检查。脚锚投影漂移0px；真实锤柄网格握点与手掌对象最大误差约5.96×10⁻⁸场景单位。重新打开保存场景后，也验证了关键帧握点恢复。
- 这不等于满足完整 Style Profile：部分蓄力引导的上边距只有3/5px，低于目标8px；结构相机实际俯角约15.39°，目标为12°。结构原始脚锚约`[124.006,220.273]`，C使用恒定偏移到`[128,232]`。这些实验差异必须在正式样板统一，不隐去。
- A 的4张包装 PNG 通过尺寸/Alpha/非空/导出边距检查；**源图第2姿态顶端和第4姿态右端触边风险仍在**。导出进行了统一缩放和底部登记，它不修复原始裁切，也不证明脚底稳定；原始包围盒底边差20px。
- B/C 的52张合成帧、分层与 JSON 已执行检查：非空、RGBA、尺寸、时序、文件完整性通过；分层重组像素误差0；脚锚数值漂移0；身体下部限定区域的 Alpha 底边漂移0。此区域指标不是语义脚掌识别。
- B/C 武器原图标注握点经独立仿射计算，与手掌标注变换的最大误差约9×10⁻¹⁴px。它只证明坐标映射，**不能证明画出来的手指包住握柄**。
- Godot 4.6.3 真正加载4条序列/52帧。通过既有 Xorg dummy 显示与 Mesa llvmpipe，实际捕获1024×720 viewport，展示96px与256px。没有把 headless dummy 渲染当作截图。
- 7个单元回归测试通过：空白/缺文件、缺Alpha、裁切风险、无效时序、脚锚漂移、零帧及缓存损坏/依赖失效。测试通过不代表所有视觉指标已实现。
- 增量构建执行第二遍命中缓存；真实单像素改锤B实验仅重建`B_hammer_b`、`C_hammer_b`，锤A输出哈希和mtime不变，所有身体层哈希不变；随后恢复原文件。初测发现无变化的拆件也重写，已修为内容改变才写入。详见`reports/incremental-validation.json`。
